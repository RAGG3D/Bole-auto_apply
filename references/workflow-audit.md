# v0.6 修订依据

本次只把 auto_apply 近期聊天中可复用的缺陷转为公共规则，不复制个人资料、帐号授权、
项目名称、特定雇主黑名单或完整聊天。最新明确纠正优先于更早追求关键词覆盖的要求。

| 观察到的纠正（当地日期） | 问题 | 修复与可复核位置 |
|---|---|---|
| 2026-09-24：不要局限 title；consultant 也可能有目标职责，但无关咨询岗被误配 | 同时漏召回、误召回 | matching.md：职责词族扩展、全文核心任务和 domain_fit；triage REVIEW |
| 2026-09-24：搜索只给很少岗位，其他平台有更多；新项目未进入 CV | 来源不全、档案过期 | 来源覆盖/失败报告，用户链接必入列，完整项目索引、must_include |
| 2026-09：资格不符/下架岗位不要创建文件夹；合规低分档未继续投递 | 生成和投递队列不一致 | 先过 generate guard 再建文件夹；所有合规 tier 同一授权队列 |
| 2026-10-01：quick apply 核对正确 CV；CV/cover title 相同 | 使用平台旧简历、跨文档冲突 | submit 明确文件路径/预览，review 检查 target_title、材料哈希 |
| 2026-10-01：扩展硬缺口的模拟包与真实包同时进行，但模拟不投递 | 模式污染和误提交风险 | Stretch 单独目录 + verdict 元数据；run/continue/force 均拦截 |
| 2026-10-07：只生成文件；新技能确认；最新日期/团队身份纠正 | 把旧资料当唯一真相、团队项目写成独立项目 | 增量事实确认及来源；CV 定稿后重写 cover；两条路线共用身份约束 |
| 2026-10-08：为覆盖 JD 改掉项目原始目的/架构 | 技能确认被误推为项目技术归属 | stretch.md：固定 strict 基线，选择合适实施环节，只追加兼容过程；无归属保留 gap |
| 2026-10-08：不能靠编错项目达到完美覆盖 | 证据报告与最终文本不一致 | verified/transferable/gap/proposed 分开，证据映射更新后再 review |

回归测试使用虚构候选和项目，覆盖雇主后缀排除、政府/红线标题误筛、相邻岗位召回、
stub/硬门槛阻断、Stretch 架构/成果保留、遗漏项目、CV/cover 冲突、过期文件审核、
真实投递隔离和 token 计数去重。测试证明程序边界；自然语言的真实程度仍需原始证据。
